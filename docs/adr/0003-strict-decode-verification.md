# 严格解码：探测提出假设，解码器验证

iconv-lite 解码默认宽松——非法字节序列静默替换为 U+FFFD，随之转码落盘即是静默乱码。决定：所有解码一律 `{fatal:true}`。auto 模式不盲信探测第一名：取 `chardet.analyse()` 的排序候选（置信度 ≥ 阈值 90）逐个严格解码，第一个能干净解码者即为源编码；显式模式遇到非法序列则该文件硬失败（"不是有效的 X 序列"）。这是 ADR-0002 数据安全立场的延伸：U+FFFD 落盘与不可映射字符同罪。

## Consequences

- 探测器永远只是假设生成器，最终裁决权在严格解码。探测标签粒度不影响正确性：chardet 对 GBK/GB2312 统一报 GB18030，按超集解码内容无损。
- 依赖 chardet `analyse()` 返回排序候选这一 API 形态；更换探测库需保持同等能力。
